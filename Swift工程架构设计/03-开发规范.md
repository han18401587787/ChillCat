## 1. Swift 编码规范

### 1.1 命名规范

#### 1.1.1 基本规则

| 类型 | 规范 | 正确示例 | 错误示例 |
|------|------|----------|----------|
| 类（Class） | PascalCase | `UserManager` | `userManager` |
| 结构体（Struct） | PascalCase | `LoginState` | `login_state` |
| 枚举（Enum） | PascalCase | `HTTPMethod` | `http_method` |
| 协议（Protocol） | PascalCase | `UserRepositoryProtocol` | `userRepository` |
| 方法（Method） | camelCase | `fetchUser()` | `Fetch_User()` |
| 属性（Property） | camelCase | `userName` | `user_name` |
| 变量（Variable） | camelCase | `isLoading` | `is_loading` |
| 常量（Constant） | camelCase | `defaultTimeout` | `kDefaultTimeout` |
| 泛型参数 | 大写单字母 | `T`, `Element` | `type` |

#### 1.1.2 协议命名

```swift
// ✅ 能力型协议 - 以 Protocol 结尾
protocol UserRepositoryProtocol { }
protocol ImageLoaderProtocol { }

// ✅ 委托型协议 - 以 Delegate 结尾
protocol LoginViewDelegate: AnyObject { }

// ✅ 数据源型协议 - 以 DataSource 结尾
protocol HomeViewDataSource: AnyObject { }
```

#### 1.1.3 枚举命名

```swift
// ✅ 枚举名 PascalCase，case 使用 camelCase
enum NetworkState {
    case connected
    case disconnected
    case connecting
}

// ✅ 带关联值的枚举
enum APIError: Error {
    case invalidURL
    case networkFailure(Error)
    case serverError(statusCode: Int, message: String)
}
```

### 1.2 代码组织

#### 1.2.1 文件内部结构

```swift
//
//  FileName.swift
//  ProjectName
//
//  Created by doudou.han on 2025-07-16.
//

import Foundation

// MARK: - Protocol
// 协议定义放在文件顶部

// MARK: - Model / State
// 数据模型、状态结构体

// MARK: - Class / Struct
// 主要实现

// MARK: - Extension
// 扩展放在主类型下方
```

#### 1.2.2 属性组织顺序

```swift
final class ExampleViewModel {
    // MARK: - Public Properties（计算属性/Published）
    @Published var state = ExampleState()

    // MARK: - Private Properties（依赖/内部状态）
    private let useCase: ExampleUseCaseProtocol
    private var cancellables = Set<AnyCancellable>()

    // MARK: - Initialization
    init(useCase: ExampleUseCaseProtocol) {
        self.useCase = useCase
    }

    // MARK: - Public Methods
    func loadData() async { }

    // MARK: - Private Methods
    private func validate() -> Bool { }
}
```

### 1.3 代码风格

#### 1.3.1 括号与空格

```swift
// ✅ 左括号不换行
if condition {
    // code
}

// ✅ 运算符前后加空格
let sum = a + b
let isEqual = (a == b)

// ✅ 冒号左边无空格，右边有空格
let dict: [String: Any] = [:]
let result: Result<Success, Failure>
```

#### 1.3.2 访问控制

```swift
// ✅ 最小化访问权限
public struct PublicAPI { }      // 公开 API
struct InternalType { }          // 模块内使用（默认 internal）
private(set) var name: String    // 只读对外
private let helper = Helper()    // 私有
```

#### 1.3.3 使用 `self` 的规则

```swift
// ✅ 仅在需要区分时使用 self
final class Example {
    private let name: String

    init(name: String) {
        self.name = name  // 参数名冲突时需要
    }

    func printName() {
        print(name)  // 无冲突时不需要 self
    }
}
```

### 1.4 安全编码

#### 1.4.1 禁止强制解包

```swift
// ❌ 禁止
let url = URL(string: string)!
let value = optionalValue!

// ✅ 使用 guard let 或 if let
guard let url = URL(string: string) else {
    throw APIError.invalidURL
}

// ✅ 使用 ?? 提供默认值
let displayName = name ?? "未知用户"
```

#### 1.4.2 循环引用防护

```swift
// ✅ 闭包中使用 [weak self]
Task { [weak self] in
    guard let self else { return }
    await self.loadData()
}

// ✅ 协议使用 class 约束
protocol LoginViewDelegate: AnyObject { }
```

#### 1.4.3 可选类型安全

```swift
// ✅ 使用 Optional Chaining
user?.profile?.name

// ✅ 使用 flatMap 处理嵌套可选
let result = optionalValue.flatMap { transform($0) }

// ✅ 使用 if let 解包
if let value = optionalValue {
    use(value)
}
```

### 1.5 文档注释

```swift
/// 用户仓库协议 - 负责用户数据的增删改查
///
/// 使用示例：
/// ```
/// let repository: UserRepositoryProtocol = UserRepository()
/// let user = try await repository.fetchUser(id: "123")
/// ```
protocol UserRepositoryProtocol {
    /// 根据 ID 获取用户信息
    /// - Parameter id: 用户唯一标识
    /// - Returns: 用户实体
    /// - Throws: `AppError.network` 网络错误
    ///           `AppError.data` 数据解析错误
    func fetchUser(id: String) async throws -> User

    /// 更新用户信息
    /// - Parameter user: 要更新的用户数据
    /// - Throws: 更新失败时抛出错误
    func updateUser(_ user: User) async throws
}
```

## 2. SwiftLint 规范

### 2.1 配置文件

```yaml
# .swiftlint.yml

# 禁用的规则
disabled_rules:
  - trailing_whitespace
  - identifier_name
  - force_cast
  - nesting
  - function_parameter_count

# 启用的可选规则
opt_in_rules:
  - empty_count
  - explicit_init
  - closure_spacing
  - overridden_super_call
  - redundant_nil_coalescing
  - sorted_imports
  - yoda_condition
  - fatal_error_message
  - first_where
  - last_where
  - toggle_bool
  - unused_import

# 路径包含/排除
included:
  - App
  - Core
  - Domain
  - Data
  - Presentation
  - Modules

excluded:
  - Pods
  - Derived
  - .build
  - Tests

# 自定义规则参数
line_length:
  warning: 120
  error: 200

file_length:
  warning: 400
  error: 600

type_body_length:
  warning: 300
  error: 500

function_body_length:
  warning: 50
  error: 100

cyclomatic_complexity:
  warning: 10
  error: 20

type_name:
  min_length: 2
  max_length: 50

identifier_name:
  min_length: 2
  max_length: 50
  excluded:
    - id
    - ok
    - to
    - vm
```

### 2.2 常用规则说明

| 规则 | 说明 | 严重度 |
|------|------|--------|
| `force_unwrapping` | 禁止强制解包 | Error |
| `unused_import` | 禁止未使用的 import | Warning |
| `redundant_optional_initialization` | 禁止冗余可选初始化 | Warning |
| `empty_count` | 使用 `isEmpty` 而非 `count == 0` | Warning |
| `sorted_imports` | import 按字母排序 | Warning |
| `closure_spacing` | 闭包花括号前后空格 | Warning |
| `overridden_super_call` | 重写方法需调用 super | Warning |

## 4. Git 规范

### 4.1 分支策略

```
main                    # 生产分支，只接受 release/hotfix 合入
├── develop             # 开发主分支
│   ├── feature/xxx     # 功能开发（从 develop 拉出，合回 develop）
│   ├── bugfix/xxx      # Bug 修复（从 develop 拉出，合回 develop）
│   └── refactor/xxx    # 重构（从 develop 拉出，合回 develop）
├── release/x.y.z       # 发布准备（从 develop 拉出，合入 main+develop）
└── hotfix/x.y.z        # 紧急修复（从 main 拉出，合入 main+develop）
```

### 4.2 分支命名规范

```
feature/STORY-123-user-login        # 功能分支
bugfix/BUG-456-login-crash          # Bug 修复
refactor/network-layer-refactor     # 重构
release/1.2.0                       # 发布分支
hotfix/1.1.1                        # 紧急修复
```

### 4.3 Commit Message 规范

#### 4.3.1 标准格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

#### 4.3.2 Type 类型

| Type | 用途 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(auth): 添加手机号登录` |
| `fix` | Bug 修复 | `fix(login): 修复空密码崩溃` |
| `docs` | 文档 | `docs: 更新 README` |
| `style` | 代码格式 | `style: 格式化代码` |
| `refactor` | 重构 | `refactor(network): 重构网络层` |
| `perf` | 性能优化 | `perf(list): 优化列表滚动性能` |
| `test` | 测试 | `test(auth): 添加登录测试用例` |
| `chore` | 构建/工具 | `chore: 更新 SwiftLint 配置` |
| `ci` | CI 配置 | `ci: 添加 GitHub Actions` |

#### 4.3.3 完整示例

```
feat(auth): 添加手机号验证码登录功能

- 支持手机号格式校验
- 支持验证码获取与验证
- 登录成功后自动跳转首页
- 添加登录状态持久化

Closes #123, #124
```

### 4.4 Code Review 规范

#### 4.4.1 Review Checklist

- [ ] 代码符合命名规范和代码组织规范
- [ ] 没有强制解包（force unwrap）
- [ ] 没有循环引用（weak/unowned 使用正确）
- [ ] 异步操作有正确的错误处理
- [ ] 协议定义合理，没有胖协议
- [ ] 单元测试覆盖核心逻辑
- [ ] 没有硬编码的字符串/数字
- [ ] 没有遗留的 TODO/FIXME
- [ ] 公共 API 有文档注释
- [ ] 没有引入不必要的依赖
- [ ] 没有敏感信息泄露（Token、Key 等）
- [ ] 国际化字符串已提取到 Localizable

#### 4.4.2 Review 流程

```
1. 开发者提交 PR
2. CI 自动运行（Lint + Test + Build）
3. 至少 1 人 Review Approve
4. 开发者 Merge（Squash Merge）
5. 删除特性分支
```

## 5. 国际化规范

### 5.1 字符串管理

```swift
// ❌ 禁止硬编码字符串
Text("登录")

// ✅ 使用 LocalizedStringKey
Text("login.title")

// ✅ 使用 String Catalog（Xcode 15+）
Text("welcome.message \(userName)")

// ✅ 带注释的本地化
Text("login.hint")
    .accessibilityLabel("login.hint")
```
