## 1. 模块化策略

采用 **Feature Module（功能模块）** 模式，每个功能模块是一个独立的逻辑单元，包含自己的 Presentation、Domain、Data 三层。

### 1.1 模块划分原则

| 原则 | 说明 |
|------|------|
| **业务边界** | 按业务功能划分，一个模块对应一个完整业务能力 |
| **复用性** | 被多个模块共用的能力下沉到 Core/Common 模块 |
| **独立演进** | 每个模块可独立开发、测试、版本管理 |
| **最小依赖** | 模块只依赖必要的 Core 模块，避免业务模块间依赖 |

### 1.2 模块类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **App** | 主工程入口，组装所有模块 | `App` |
| **Core** | 基础能力，被所有模块依赖 | `CoreModule` |
| **CommonUI** | 公共 UI 组件与主题 | `CommonUIModule` |
| **Feature** | 业务功能模块 | `AuthModule`, `HomeModule` |
| **Service** | 跨模块服务 | `AnalyticsModule`, `PushModule` |

## 2. 模块划分方案

### 2.1 模块清单

```
App（主工程）

├── CommonUIModule          # 公共 UI 组件、主题、样式

│
├── AnalyticsModule         # 统计分析（Service）

```

### 2.2 模块依赖关系

```
                        ┌─────────────┐
                        │     App     │
                        └──────┬──────┘
                               │
          ┌────────────────────┼────────────────────┐
          │                    │                    │
          ▼                    ▼                    ▼
   ┌──────────┐        ┌──────────┐        ┌──────────┐
   │ AuthMod  │        │ HomeMod  │        │ProfileMod│
   └────┬─────┘        └────┬─────┘        └────┬─────┘
        │                   │                   │
        └──────────┬────────┘───────────────────┘
                   │
                   ▼
          ┌────────────────┐
          │   CoreModule   │
          │  CommonUIModule│
          └────────────────┘
```

**依赖规则：**
- Feature 模块 → CoreModule（必需）
- Feature 模块 → CommonUIModule（可选）
- Feature 模块 → Feature 模块（禁止）
- 所有模块 → 系统库（允许）

#### 2.3.2 事件总线（松耦合）

```swift
// CoreModule/Sources/Events/EventBus.swift

import Foundation

/// 事件总线 - 用于模块间松耦合通信
public final class EventBus {
    public static let shared = EventBus()
    private var observers: [String: [(Any) -> Void]] = [:]

    private init() {}

    public func post<T>(_ event: T) {
        let key = String(describing: T.self)
        observers[key]?.forEach { handler in
            handler(event)
        }
    }

    public func on<T>(_ eventType: T.Type, handler: @escaping (T) -> Void) -> AnyObject {
        let key = String(describing: T.self)
        let box: (Any) -> Void = { value in
            guard let value = value as? T else { return }
            handler(value)
        }
        observers[key, default: []].append(box)
        return self as AnyObject
    }
}

// 定义事件
public struct UserLoggedInEvent {
    public let user: User
}

public struct UserLoggedOutEvent {}

// 发送事件
EventBus.shared.post(UserLoggedInEvent(user: user))

// 监听事件
_ = EventBus.shared.on(UserLoggedInEvent.self) { event in
    print("用户登录: \(event.user.name)")
}
```

### 3.3 模块对外接口

```swift
// HomeModule/Sources/Public/HomeModuleAPI.swift

import SwiftUI

/// Home 模块对外公共接口
public enum HomeModuleAPI {

    /// 获取首页视图（主入口）
    @MainActor
    public static func makeHomeView(
        coordinator: AppCoordinatorProtocol
    ) -> some View {
        let diContainer = HomeDIContainer()
        let viewModel = diContainer.makeHomeViewModel(coordinator: coordinator)
        return HomeView(viewModel: viewModel)
    }

    /// 获取首页数据预取器
    public static func makeHomePrefetcher() -> HomeDataPrefetching {
        return HomeDataPrefetcher()
    }
}

/// 模块内部依赖容器
final class HomeDIContainer {
    func makeHomeViewModel(coordinator: AppCoordinatorProtocol) -> HomeViewModel {
        let repository = HomeRepository(
            remoteDataSource: HomeRemoteDataSource(apiClient: resolveAPIClient()),
            localDataSource: HomeLocalDataSource()
        )
        let fetchUseCase = FetchHomeItemsUseCase(repository: repository)
        return HomeViewModel(
            fetchUseCase: fetchUseCase,
            coordinator: coordinator
        )
    }

    private func resolveAPIClient() -> APIClientProtocol {
        // 从全局容器获取
        return AppDependencyContainer.shared.resolve()
    }
}
```

## 4. 模块化最佳实践

### 4.1 模块创建流程

```
1. 评估业务边界 → 2. 定义模块接口 → 3. 创建 Package.swift
4. 实现内部逻辑 → 5. 编写单元测试 → 6. 注册到主工程
```

### 4.2 模块化注意事项

| 注意事项 | 说明 |
|----------|------|
| **避免循环依赖** | 模块 A 依赖 B，B 不能依赖 A |
| **控制暴露面** | `public` 只给必要的接口，内部用 `internal` |
| **版本管理** | 模块可独立版本号，通过语义化版本管理 |
| **编译优化** | 模块化有助于增量编译，减少编译时间 |
| **资源隔离** | 每个模块的资源文件放在模块内管理 |

### 4.3 模块化反模式

```swift
// ❌ 反模式：模块间直接依赖
import AuthModule
import HomeModule

// ❌ 反模式：共享可变全局状态
public var globalUserState: UserState?

// ❌ 反模式：模块内直接访问其他模块的内部类型
AuthModule.InternalAuthHelper.doSomething()

// ✅ 正确做法：通过协议接口通信
let authService: AuthServiceProtocol = container.resolve()
```

## 5. 模块化迁移策略

### 5.1 从单体到模块化

```
阶段一：识别边界         阶段二：提取 Core         阶段三：拆分 Feature
┌──────────────┐       ┌──────────────┐          ┌──────────────┐
│    Monolith  │  →    │  CoreModule  │    →     │  AuthModule  │
│              │       │  + Monolith  │          │  HomeModule  │
└──────────────┘       └──────────────┘          │  ...         │
                                                  └──────────────┘
```

### 5.2 迁移检查清单

- [ ] Core 模块已提取完成，无业务逻辑
- [ ] CommonUI 模块已提取公共组件
- [ ] 模块间依赖关系已梳理清晰
- [ ] 跨模块通信方案已确定（协议/事件/路由）
- [ ] 各模块已独立编译通过
- [ ] 主工程已集成所有模块
- [ ] 所有测试用例通过
