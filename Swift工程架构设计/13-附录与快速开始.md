## 1. 快速开始

### 1.1 环境要求

| 工具 | 版本要求 |
|------|----------|
| Xcode | 16.0+ |
| Swift | 5.9+ |
| iOS 部署目标 | 15.0+ |
| CocoaPods（可选） | 1.15+ |
| SwiftLint | 最新版 |
| SwiftFormat | 最新版 |

### 1.2 项目初始化

```bash
# 1. 克隆项目
git clone git@github.com:example/ProjectName.git
cd ProjectName

# 2. 运行初始化脚本
chmod +x Scripts/setup.sh
./Scripts/setup.sh

# 3. 打开项目
open ProjectName.xcodeproj

# 4. 选择 Scheme 并运行
# 或使用命令行
xcodebuild build \
    -scheme ProjectName \
    -sdk iphonesimulator \
    -destination 'platform=iOS Simulator,name=iPhone 16,OS=18.0'
```

### 1.3 常用命令

```bash
# 运行所有测试
xcodebuild test \
    -scheme ProjectName \
    -sdk iphonesimulator \
    -destination 'platform=iOS Simulator,name=iPhone 16,OS=18.0'

# 运行指定测试类
xcodebuild test \
    -scheme ProjectName \
    -only-testing:LoginViewModelTests

# 代码规范检查
swiftlint --strict
swiftformat --lint .

# 代码格式化
swiftformat .

# 生成 Xcode 项目（XcodeGen）
xcodegen generate

# 清理 DerivedData
rm -rf ~/Library/Developer/Xcode/DerivedData
```

## 3. 架构决策记录（ADR）

### 3.1 ADR 模板

```markdown
# ADR-{编号}: {标题}

## 状态
[提议 | 接受 | 已废弃 | 已替换]

## 上下文
描述需要做决策的背景和原因。

## 决策
描述做出的决定。

## 理由
说明选择这个方案的原因。

## 后果
描述这个决策带来的影响。

## 替代方案
列出考虑过的其他方案和放弃的原因。
```

### 3.2 ADR 示例

```markdown
# ADR-001: 使用 SwiftUI 作为主要 UI 框架

## 状态
接受

## 上下文
项目需要选择 UI 框架。iOS 15+ 已支持 SwiftUI 的大部分功能。

## 决策
使用 SwiftUI 作为主要 UI 框架，UIKit 仅在需要复杂交互时使用。

## 理由
- SwiftUI 声明式语法开发效率更高
- 与 MVVM 模式天然契合
- iOS 15+ 已覆盖 SwiftUI 核心功能
- 代码量比 UIKit 减少约 40%

## 后果
- 需要 iOS 15+ 部署目标
- 复杂动画和自定义组件仍需 UIKit 辅助
- 团队需要 SwiftUI 培训

## 替代方案
- 纯 UIKit：开发效率低，代码量大
- React Native：引入跨平台复杂度
- Flutter：与原生生态割裂
```

## 4. 常见问题 FAQ

### 4.1 架构相关

**Q: 什么时候使用 UIKit 而不是 SwiftUI？**
A: 当需要以下能力时使用 UIKit：
- 复杂的自定义动画
- UICollectionView 的高级布局
- 与旧代码混编
- 需要精细的运行时控制

**Q: 模块间如何通信？**
A: 三种方式：
1. 协议接口（推荐）：模块定义公共协议
2. 事件总线：一对多松耦合通知
3. Coordinator：页面路由跳转

### 4.2 开发相关

**Q: 如何处理循环依赖？**
A: 使用以下方式避免：
1. 依赖注入反转依赖方向
2. 使用 weak 引用
3. 提取公共模块

**Q: 如何处理异步操作中的错误？**
A: 统一使用 `async/await` + `AppError`：
```swift
do {
    let result = try await useCase.execute()
} catch {
    let appError = error.asAppError
    // 统一处理
}
```

### 4.3 测试相关

**Q: 如何测试异步代码？**
A: 使用 async/await 测试：
```swift
func test_asyncOperation() async {
    let result = try? await useCase.execute()
    XCTAssertNotNil(result)
}
```

**Q: 如何 Mock 网络请求？**
A: 通过协议抽象网络层，测试时注入 MockAPIClient。
