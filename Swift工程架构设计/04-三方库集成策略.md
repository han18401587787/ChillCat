# 04 - 三方库集成策略

> **版本：** v1.0 | **作者：** doudou.han | **日期：** 2025-07-16

## 1. 集成原则

### 1.1 核心原则

| 原则 | 说明 |
|------|------|
| **必要性** | 优先使用系统 API，确需三方库时再引入 |
| **稳定性** | 选择活跃维护、社区广泛使用、API 稳定的库 |
| **抽象隔离** | 三方库通过封装层隔离，业务代码不直接依赖 |
| **版本锁定** | 锁定主版本号，避免破坏性更新 |
| **最小引入** | 只引入需要的子模块，避免全量引入 |
| **许可证** | 优先 MIT/Apache 2.0 许可证 |

### 1.2 引入决策流程

```
需要某个能力
    │
    ▼
系统 API 是否满足？ ──是──→ 使用系统 API
    │
    否
    │
    ▼
是否有成熟的三方库？ ──否──→ 自实现
    │
    是
    │
    ▼
评估：活跃度/稳定性/体积/许可证
    │
    ▼
通过封装层引入
```

## 2. 推荐三方库清单

### 2.1 网络层

| 库名 | 用途 | 推荐度 | 替代方案 |
|------|------|--------|----------|
| **系统 URLSession** | HTTP 请求 | ⭐⭐⭐⭐⭐ | - |
| Alamofire | 高级网络封装 | ⭐⭐⭐⭐ | Moya, APIKit |
| Moya | 网络抽象层 | ⭐⭐⭐⭐ | - |

**推荐：** 优先使用系统 `URLSession` + `async/await`，仅在需要复杂拦截链、重试策略时引入 Alamofire。

### 2.2 图片加载

| 库名 | 用途 | 推荐度 | 替代方案 |
|------|------|--------|----------|
| **Kingfisher** | 异步图片加载/缓存 | ⭐⭐⭐⭐⭐ | Nuke, SDWebImage |
| Nuke | 高性能图片加载 | ⭐⭐⭐⭐ | - |

**推荐：** Kingfisher，社区活跃、功能全面、Swift 原生。

### 2.3 数据持久化

| 库名 | 用途 | 推荐度 | 替代方案 |
|------|------|--------|----------|
| **SwiftData** | 本地数据库（iOS 17+） | ⭐⭐⭐⭐⭐ | - |
| CoreData | 本地数据库（系统） | ⭐⭐⭐⭐ | - |
| GRDB | SQLite 封装 | ⭐⭐⭐⭐ | FMDB |
| Realm | 移动端数据库 | ⭐⭐⭐ | - |

**推荐：** 新项目优先使用 SwiftData，需兼容 iOS 15/16 使用 CoreData 或 GRDB。

### 2.4 响应式编程

| 库名 | 用途 | 推荐度 | 替代方案 |
|------|------|--------|----------|
| **Combine（系统）** | 响应式编程 | ⭐⭐⭐⭐⭐ | - |
| RxSwift | 响应式编程 | ⭐⭐⭐⭐ | - |

**推荐：** 优先使用系统 Combine，仅在需要跨平台或复杂操作符时考虑 RxSwift。

### 2.5 UI 组件

| 库名 | 用途 | 推荐度 | 替代方案 |
|------|------|--------|----------|
| **SwiftUI（系统）** | UI 构建 | ⭐⭐⭐⭐⭐ | - |
| Lottie | 动画 | ⭐⭐⭐⭐⭐ | - |
| ProgressHUD | 加载提示 | ⭐⭐⭐⭐ | SVProgressHUD |
| ToastUI | Toast 提示 | ⭐⭐⭐⭐ | 自实现 |

### 2.6 工具类

| 库名 | 用途 | 推荐度 | 替代方案 |
|------|------|--------|----------|
| **Factory** | 依赖注入 | ⭐⭐⭐⭐⭐ | Swinject, Needle |

## 3. 封装策略

### 3.1 三层封装模型

```
┌────────────────────────────────────────────┐
│               Business Code                 │
│         (只依赖 Protocol/Abstraction)        │
└──────────────────┬─────────────────────────┘
                   │
┌──────────────────▼─────────────────────────┐
│           Adapter / Wrapper Layer           │
│        (协议实现，封装三方库 API)             │
│       可替换：替换实现类即可切换三方库         │
└──────────────────┬─────────────────────────┘
                   │
┌──────────────────▼─────────────────────────┐
│            Third-Party Library              │
│         (Alamofire / Kingfisher / ...)      │
└────────────────────────────────────────────┘
```

### 3.2 网络层封装示例

```swift
// Core/Networking/APIClient.swift

import Foundation

/// 网络客户端协议 - 业务代码只依赖此协议
protocol APIClientProtocol {
    func request<T: Decodable>(_ endpoint: APIEndpoint) async throws -> T
    func request(_ endpoint: APIEndpoint) async throws -> Data
}

/// API 端点协议
protocol APIEndpoint {
    var baseURL: URL { get }
    var path: String { get }
    var method: HTTPMethod { get }
    var headers: [String: String]? { get }
    var body: Encodable? { get }
    var queryParameters: [String: String]? { get }
    var timeout: TimeInterval { get }
}

// MARK: - 使用系统 URLSession 的实现

final class URLSessionAPIClient: APIClientProtocol {
    private let session: URLSession
    private let interceptor: RequestInterceptor?

    init(session: URLSession = .shared, interceptor: RequestInterceptor? = nil) {
        self.session = session
        self.interceptor = interceptor
    }

    func request<T: Decodable>(_ endpoint: APIEndpoint) async throws -> T {
        let data = try await request(endpoint)
        return try JSONDecoder().decode(T.self, from: data)
    }

    func request(_ endpoint: APIEndpoint) async throws -> Data {
        var request = try buildRequest(from: endpoint)
        request = try await interceptor?.intercept(request) ?? request

        let (data, response) = try await session.data(for: request)

        guard let httpResponse = response as? HTTPURLResponse else {
            throw APIError.invalidResponse
        }
        try validateResponse(httpResponse)

        return data
    }

    // ... buildRequest, validateResponse 实现
}
```

### 3.3 图片加载封装示例

```swift
// Core/Image/ImageLoader.swift

import SwiftUI

/// 图片加载器协议
protocol ImageLoaderProtocol {
    func loadImage(from url: URL) async throws -> UIImage
    func prefetchImages(urls: [URL]) async
    func clearCache()
}

// MARK: - 使用系统 URLSession 的实现

final class SystemImageLoader: ImageLoaderProtocol {
    private let cache = NSCache<NSURL, UIImage>()
    private let session: URLSession

    init(session: URLSession = .shared) {
        self.session = session
        cache.countLimit = 100
        cache.totalCostLimit = 50 * 1024 * 1024
    }

    func loadImage(from url: URL) async throws -> UIImage {
        if let cached = cache.object(forKey: url as NSURL) {
            return cached
        }
        let (data, _) = try await session.data(from: url)
        guard let image = UIImage(data: data) else {
            throw ImageLoaderError.invalidData
        }
        cache.setObject(image, forKey: url as NSURL)
        return image
    }

    func prefetchImages(urls: [URL]) async {
        await withTaskGroup(of: Void.self) { group in
            for url in urls {
                group.addTask { _ = try? await self.loadImage(from: url) }
            }
        }
    }

    func clearCache() { cache.removeAllObjects() }
}

// MARK: - SwiftUI 图片加载 ViewModifier

struct ImageLoaderViewModifier: ViewModifier {
    let url: URL?
    @State private var image: UIImage?

    func body(content: Content) -> some View {
        if let image = image {
            Image(uiImage: image)
                .resizable()
        } else {
            content
                .task {
                    guard let url = url else { return }
                    image = try? await ImageLoader.shared.loadImage(from: url)
                }
        }
    }
}

extension View {
    func loadImage(from url: URL?) -> some View {
        modifier(ImageLoaderViewModifier(url: url))
    }
}
```

### 3.4 日志封装示例

```swift
// Core/Logging/Logger.swift

import OSLog

/// 日志协议
protocol LoggerProtocol {
    func debug(_ message: String, file: String, function: String, line: Int)
    func info(_ message: String, file: String, function: String, line: Int)
    func warning(_ message: String, file: String, function: String, line: Int)
    func error(_ message: String, file: String, function: String, line: Int)
}

// MARK: - 使用系统 OSLog 的实现

final class OSLogger: LoggerProtocol {
    private let osLog: OSLog
    private let minLevel: LogLevel

    init(subsystem: String = Bundle.main.bundleIdentifier ?? "com.app",
         category: String = "default",
         minLevel: LogLevel = .debug) {
        self.osLog = OSLog(subsystem: subsystem, category: category)
        self.minLevel = minLevel
    }

    func debug(_ message: String, file: String = #file, function: String = #function, line: Int = #line) {
        log(level: .debug, message: message, file: file, function: function, line: line)
    }

    // ... 其他方法实现

    private func log(level: LogLevel, message: String, file: String, function: String, line: Int) {
        guard level >= minLevel else { return }
        let fileName = (file as NSString).lastPathComponent
        let msg = "[\(fileName):\(line)] \(function) > \(message)"
        os_log("%{public}@", log: osLog, type: level.osLogType, msg)
    }
}
```

## 4. SPM 依赖管理

### 4.1 Package.swift 配置

```swift
// swift-tools-version: 5.9
import PackageDescription

let package = Package(
    name: "ProjectName",
    platforms: [.iOS(.v15)],
    dependencies: [
        // 网络层
        .package(url: "https://github.com/Alamofire/Alamofire.git",
                 from: "5.9.0"),

        // 图片加载
        .package(url: "https://github.com/onevcat/Kingfisher.git",
                 from: "7.12.0"),

        // 动画
        .package(url: "https://github.com/airbnb/lottie-spm.git",
                 from: "4.5.0"),

        // 依赖注入
        .package(url: "https://github.com/hmlongco/Factory.git",
                 from: "2.3.0"),

        // 测试
        .package(url: "https://github.com/pointfreeco/swift-snapshot-testing.git",
                 from: "1.17.0"),
    ],
    targets: [
        .target(
            name: "CoreModule",
            dependencies: [
                "Alamofire",
                "Kingfisher",
                .product(name: "Factory", package: "Factory"),
            ]
        ),
        // ...
    ]
)
```

### 4.2 版本锁定策略

```swift
// 使用精确版本锁定（推荐用于生产）
.package(url: "https://github.com/Alamofire/Alamofire.git",
         exact: "5.9.0")

// 使用版本范围（推荐用于开发）
.package(url: "https://github.com/Alamofire/Alamofire.git",
         from: "5.9.0")  // >= 5.9.0, < 6.0.0

// 使用分支（不推荐，仅用于临时测试）
.package(url: "https://github.com/Alamofire/Alamofire.git",
         branch: "master")
```

### 4.3 依赖冲突解决

```swift
// 方案一：统一版本
.package(url: "https://github.com/onevcat/Kingfisher.git",
         from: "7.12.0")

// 方案二：使用 revision 锁定 commit
.package(url: "https://github.com/onevcat/Kingfisher.git",
         revision: "a1b2c3d4e5f6...")

// 方案三：fork 并修改
.package(url: "https://github.com/your-org/Kingfisher.git",
         from: "7.12.0")
```

## 5. 依赖版本管理流程

### 5.1 更新流程

```
1. 检查更新：查看库的 Release Notes
2. 评估影响：是否有 Breaking Changes
3. 更新版本：修改 Package.swift
4. 编译验证：确保项目编译通过
5. 运行测试：所有测试用例通过
6. 回归测试：核心功能验证
7. 提交 PR：注明版本变更内容
```

## 6. 自实现 vs 引入三方库决策树

```
需要某个功能
    │
    ├── 系统 API 是否足够？
    │   ├── 是 → 使用系统 API ✅
    │   └── 否
    │
    ├── 功能是否简单（< 200 行）？
    │   ├── 是 → 自实现 ✅
    │   └── 否
    │
    ├── 是否有成熟的三方库？
    │   ├── 否 → 自实现 ✅
    │   └── 是
    │
    ├── 库是否活跃维护（最近 6 个月有更新）？
    │   ├── 否 → 自实现 ✅
    │   └── 是
    │
    ├── 库的体积是否可接受？
    │   ├── 否 → 自实现或找替代 ✅
    │   └── 是
    │
    └── 引入 ✅（需封装隔离）
```
