# Skill 2: 自动化可行性评估

> 判断哪些页面/链路适合自动化，哪些需要换策略

## 评估框架

每个测试场景从以下维度打分（1-5）：

| 维度 | 权重 | 说明 |
|------|------|------|
| 稳定性 | 30% | 页面结构和控件是否频繁变更 |
| 可定位性 | 25% | 关键元素是否有稳定 identifier |
| 业务价值 | 25% | 链路是否为核心流程 |
| 执行成本 | 10% | 单次执行耗时和资源消耗 |
| 维护成本 | 10% | 页面变更时脚本修改工作量 |

**总分 ≥ 3.5** → 适合自动化  
**总分 2.5-3.5** → 部分可自动化  
**总分 < 2.5** → 建议手工/接口测试

## 自动化策略建议

### 第一梯队（立即自动化）
- ✅ 登录 → 首页 → 情绪打卡
- ✅ Tab 导航切换
- ✅ CBT / 身体扫描 / 感恩日记 完整流程
- ✅ 设置页各项入口

### 第二梯队（逐步自动化）
- ⚠️ AI 倾听官对话（需处理等待）
- ⚠️ 树洞发帖 + 共鸣（需处理动态列表）
- ⚠️ 会员中心浏览（不触发真实支付）

### 第三梯队（接口/手工为主）
- ⚠️ 真实支付/退款（沙箱环境）
- ⚠️ 账号删除（仅验证 UI）
- ❌ 分享面板（系统 UI 不可控）
- ❌ 推送通知（系统级）
