## 1. 总体演进路线

根据业务发展不同阶段，服务端架构从简单到复杂分为三个阶段：

```
阶段一：单体服务         阶段二：模块拆分             阶段三：微服务
┌──────────────┐       ┌──────────────────┐       ┌──────────────────┐
│   All-in-One │   →   │  API Server       │   →   │  服务网格         │
│  单进程部署   │       │  + 独立模块        │       │  Service Mesh    │
│              │       │  + 缓存层          │       │  + 事件驱动       │
└──────────────┘       └──────────────────┘       └──────────────────┘
     MVP/早期              增长期                     成熟期
```

## 2. 阶段一：单体服务（MVP / 早期）

### 2.1 适用场景

- 用户量 < 1万 DAU
- 1~2 人开发维护
- 快速验证业务模式
- 功能简单，API 数量 < 50 个

### 2.2 技术选型

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| **语言** | Go 或 Node.js (TypeScript) | Go 性能好、部署简单；Node.js 开发快 |
| **Web 框架** | Go: Gin / Echo | 轻量、高性能、社区活跃 |
| | Node.js: Express / Fastify | 生态丰富、上手快 |
| **数据库** | PostgreSQL | 关系型数据库，功能全面，支持 JSON |
| **缓存** | Redis | 会话管理、缓存加速 |
| **部署** | 单台云服务器 (2C4G) | 阿里云/腾讯云轻量服务器 |
| **反向代理** | Nginx | 静态资源、HTTPS 终止、反向代理 |
| **CI/CD** | GitHub Actions + rsync/SCP | 简单自动化部署 |

|-----------|------|

| `30000-39999` | 会员模块错误 |
| `40000-49999` | 业务模块错误 |
| `50000-59999` | 服务端内部错误 |

#### 建表 SQL

```sql
-- 用户表
CREATE TABLE users (
    id          BIGSERIAL PRIMARY KEY,
    username    VARCHAR(64)  NOT NULL UNIQUE,
    email       VARCHAR(255) NOT NULL UNIQUE,
    password    VARCHAR(255) NOT NULL,
    nickname    VARCHAR(64)  NOT NULL DEFAULT '',
    avatar      VARCHAR(512) NOT NULL DEFAULT '',
    status      SMALLINT     NOT NULL DEFAULT 1, -- 1:正常 0:禁用
    created_at  TIMESTAMP    NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMP    NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_username ON users(username);

-- 会员信息表
CREATE TABLE member_info (
    id          BIGSERIAL PRIMARY KEY,
    user_id     BIGINT       NOT NULL REFERENCES users(id),
    member_type VARCHAR(32)  NOT NULL DEFAULT '', -- monthly/quarterly/yearly/permanent
    status      VARCHAR(32)  NOT NULL DEFAULT 'none', -- active/expired/cancelled/none
    start_date  TIMESTAMP,
    end_date    TIMESTAMP,
    auto_renew  BOOLEAN      NOT NULL DEFAULT FALSE,
    created_at  TIMESTAMP    NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMP    NOT NULL DEFAULT NOW()
);

CREATE UNIQUE INDEX idx_member_info_user ON member_info(user_id);

-- 会员订单表
CREATE TABLE member_orders (
    id              BIGSERIAL PRIMARY KEY,
    user_id         BIGINT       NOT NULL REFERENCES users(id),
    order_no        VARCHAR(64)  NOT NULL UNIQUE,
    member_type     VARCHAR(32)  NOT NULL,
    order_status    VARCHAR(32)  NOT NULL DEFAULT 'pending', -- pending/success/failed/refunded
    amount          DECIMAL(10,2) NOT NULL DEFAULT 0,
    payment_method  VARCHAR(32)  NOT NULL DEFAULT '',
    start_date      TIMESTAMP,
    end_date        TIMESTAMP,
    paid_at         TIMESTAMP,
    created_at      TIMESTAMP    NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMP    NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_orders_user ON member_orders(user_id);
CREATE INDEX idx_orders_no ON member_orders(order_no);
```

## 3. 阶段二：模块拆分（增长期）

### 3.1 适用场景

- 用户量 1万 ~ 10万 DAU
- 3~5 人开发团队
- 功能增多，API > 50 个

### 3.3 技术选型升级

| 组件 | 阶段一 | 阶段二 |
|------|--------|--------|
| **API 网关** | Nginx | OpenResty / Kong / APISIX |
| **服务通信** | 直接调用 | gRPC / HTTP |
| **服务发现** | 无 | Consul / etcd |
| **配置中心** | 环境变量 | Apollo / Nacos |

| **CDN** | 无 | 阿里云CDN / 腾讯云CDN |

### 3.5 gRPC 协议定义

```protobuf
// proto/member/service.proto

syntax = "proto3";

package member;

option go_package = "chillcat/member-service/proto";

service MemberService {
    rpc GetMemberInfo (GetMemberInfoRequest) returns (GetMemberInfoResponse);
    rpc PurchaseMember (PurchaseMemberRequest) returns (PurchaseMemberResponse);
    rpc RenewMember (RenewMemberRequest) returns (RenewMemberResponse);
    rpc CancelAutoRenew (CancelAutoRenewRequest) returns (CancelAutoRenewResponse);
}

message MemberInfo {
    int64  user_id = 1;
    string member_type = 2;
    string status = 3;
    string start_date = 4;
    string end_date = 5;
    bool   auto_renew = 6;
}

message GetMemberInfoRequest {
    int64 user_id = 1;
}

message GetMemberInfoResponse {
    int32 code = 1;
    string message = 2;
    MemberInfo data = 3;
}

message PurchaseMemberRequest {
    int64  user_id = 1;
    string product_id = 2;
    string payment_method = 3;
}

message PurchaseMemberResponse {
    int32 code = 1;
    string message = 2;
    MemberInfo data = 3;
    string order_no = 4;
}
```

### 4.3 技术选型

            │                 │

                   ▼
           ┌──────────────┐

### 4.5 数据库设计（阶段三）

#### 分库分表策略

```sql
-- 按 user_id 哈希分片（16个分片）
-- shard_00 ~ shard_15

-- 每个分片包含：
-- chillcat_user_00  ~ chillcat_user_15
-- chillcat_member_00 ~ chillcat_member_15

-- 分片路由规则
func getShardDB(userID int64) string {
    shard := userID % 16
    return fmt.Sprintf("chillcat_shard_%02d", shard)
}
```

## 5. 各阶段对比总结

| 维度 | 阶段一：单体 | 阶段二：模块拆分 | 阶段三：微服务 |
|------|-------------|----------------|---------------|
| **DAU** | < 1万 | 1万 ~ 10万 | > 10万 |
| **团队规模** | 1~2 人 | 3~5 人 | 5+ 人 |
| **语言** | Go / Node.js | Go | Go + Java |
| **部署方式** | 单机 Docker | K8s (minimal) | K8s + Service Mesh |
| **数据库** | 单库 PostgreSQL | 按服务独立库 | 分库分表 + 读写分离 |
| **缓存** | 单机 Redis | Redis + 本地缓存 | Redis Cluster |
| **API 网关** | Nginx | OpenResty / Kong | APISIX / Kong |
| **服务发现** | 无 | Consul | K8s + Istio |
| **可观测性** | 无 | Prometheus + Grafana | Prometheus + Grafana + ELK + SkyWalking |
| **消息队列** | 无 | RabbitMQ | Kafka |
| **CI/CD** | GitHub Actions | GitLab CI | GitLab CI + ArgoCD |
| **成本** | ~100元/月 | ~1000元/月 | ~5000+元/月 |

## 6. 推荐演进路径

```
MVP（1个月）
  └── Go + Gin + PostgreSQL + Redis + 单机部署
       │
增长期（3-6个月）
  ├── 拆分服务（user/member/payment）
  ├── 接入 API 网关
  ├── 引入可观测性
  └── 迁移到 K8s
       │
成熟期（6个月+）
  ├── Service Mesh
  ├── 事件驱动 + CQRS
  ├── 分库分表
  └── 多活部署
```
